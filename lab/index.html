Personal builds

Things I built because I wanted them to exist. Same habits as the work, just pointed at home.

The job search machine

Problem
A serious search is a pipeline, and running a pipeline by hand out of browser tabs eats the hours that should go into the actual applications.
Built
Research and drafting run per company, with a gate that stops anything that shouldn't go out. Outreach drafts show up in a morning digest with one-tap approve and send. The work samples carry a beacon that pings my phone when somebody opens one. Friday I get a scorecard. Notion holds all of it.
Stack
claude code / n8n / notion / gmail

Life OS in Notion

Problem
Life admin scattered across inboxes, memory, and paper means the same decisions get made twice and the maintenance gets remembered late.
Built
An operating manual, an Inbox, a Knowledge Base, a Decisions Log, Active Sprints, a Weekly Review, and a Home and Garage Maintenance database. Three hooks feed it so I don't have to: forwarded email lands in the Inbox, a webhook writes to the Knowledge Base, and Home Assistant logs maintenance on its own.
Stack
notion / n8n / home assistant / gmail

Home Assistant

Problem
A house full of smart devices from different eras, none of them speaking to each other, half of them running someone's cloud.
Built
Three waves of cleanup: naming conventions, consolidating integrations, retiring old hardware. Then the automations, including a goodnight lockdown and a doorbell chime. Maintenance events post themselves to the Life OS database in Notion.
Stack
home assistant / n8n / notion

Wardrobe app

Problem
Getting dressed for the right context is a lookup problem, and nobody in the house wanted to be the one answering it.
Built
Wardrobe and Outfits databases in Notion with a standardized schema across 14 use contexts, a Cloudflare Worker API on top, AI photo cataloguing to get items in without data entry (289 items in so far), and an iOS app in progress with TestFlight for family use.
Stack
notion / cloudflare workers / ios (testflight)

Event pacing dashboard

Problem
An events team watching registration and revenue pacing across a portfolio should not have to assemble the picture by hand every Monday.
Built
A standalone app on the Bizzabo API for a media company's events team: registration and revenue pacing, year over year comparisons, promo attribution, Monday digests, and an AI question-and-answer layer on top of the data.
Stack
bizzabo api / ai q&a layer

An annual show programmed on an Ignite cue system and synced to music, with a 2-second delay baked into every cue to cover igniter lag. You get one take a year.

ignite / a music track / a checklist
