The operating playbook and AI

Lifecycle standards, prompt libraries, QA checklists, and governance: the operating system that lets a two-person team run 10+ concurrent programs, with custom GPTs doing the trainable work.

Problem

Ten or more concurrent lifecycle programs and two people to run them. At that ratio, every unwritten standard becomes a bottleneck and every judgment call becomes a queue behind one person. AI could absorb a lot of the trainable work, but AI without rails produces confident garbage at scale, which is worse than the bottleneck.

What I built

  • Lifecycle standards first: what a program is, what every email must contain, what launch-ready means. Written down, so quality stopped depending on memory.
  • Prompt libraries for the recurring work, built and versioned like any other asset.
  • QA checklists that gate everything before it ships, human or machine made.
  • Governance: what AI is allowed to touch, what needs human review, and who owns the output.
  • Custom ChatGPT Enterprise GPTs trained on the standards, so the trainable work runs through them.
  • A two-bucket contractor model separating trainable execution from specialized expertise, so outside spend goes where judgment is actually required.
  • Value reporting frameworks for the martech stack, tying tool spend to measurable contribution.

Stack

chatgpt enterprise (custom gpts) / claude code / n8n / smartsheet / monday.com

Outcome

Campaign work modeled at 149 to 206 specialist hours has been delivered in roughly 71 to 74 hours by one AI-assisted operator: about a 60% reduction, projected to reach about 79% once the lifecycle agents launch. The modeling is against specialist-hour benchmarks, and the QA gate is why the speed does not cost quality.

Order of operationsThe prompt libraries, QA checklists, and governance existed before any agent went live. Rails first, then speed.
In developmentThree AI agents are in build: a lifecycle engine, a media planning assistant with a seller pilot live, and an owned concierge.
